# 🎭 演出提示单（Cue Sheet）· 小剧场排练用

基于 **Node.js / Express + 原生 HTML/CSS/JavaScript** 的单页小工具，无任何前端构建与框架。
每条演出提示（Cue）记录：

- **名称**
- **独占设备通道**（如：灯光台 A、追光 B、调音台 M）
- **持续秒数**
- **开始时间**，二选一：
  - 固定：从演出开始的第 N 秒；
  - 相对：在**另一条提示结束后**延迟 N 秒开始。

新增 / 修改提示后，服务端会**递归重算所有后继提示**的开始与结束时间；时间轴按
**左闭右开 `[开始, 结束)`** 区间绘制，自动标出同一通道上互相重叠的提示及**冲突时段**。
首尾相接（前一条结束时刻 = 后一条开始时刻）不算冲突。**冲突允许保留**，仅作排练现场调整的提醒。

数据保存在本地 JSON 文件（默认 `./data/cues.json`），原子写入（先写临时文件再 rename）。

### 片段排练单

在不改动原提示单的前提下，可随时按**原演出时间窗 `[起, 止)`**（左闭右开、需为正长度）截取一张**独立的片段排练单**用于分场排练：

- 服务端按现有重算结果，选出与窗口有**正长度交集**的提示，把区间截到窗口并整体**平移到 0**；
- 前置与后继都入选、且提示未跨左边界时，**保留相对前置关系**（延迟按截取后的端点重算）；
- **前置未入选**片段、或**提示跨左边界**时，自动改为「固定开始」，因此下载的 JSON **没有任何悬空引用**，重算时刻与截取结果严格一致；
- 页面预览片段时间轴、入选提示表，以及按左闭右开规则计算的**片段内通道冲突**；
- 点「下载片段 JSON」得到可作为独立提示单使用的文件（含 `sourceWindow` 与完整的 `cues`，可直接再次导入/重算）；
- 窗口非法（缺失、非数字、负数、起 ≥ 止）返回 **400**；源提示存在时间未定（缺失引用/循环依赖）时无法截取，返回 **409**。

## 一条命令启动（Docker Compose）

依赖安装（镜像构建时 `npm install`）与数据初始化（首次启动自动写入示例 JSON）都包含在这一条命令里：

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

> 首次启动若宿主机 `./data/cues.json` 不存在，会自动创建 `data/` 目录并写入一组示例提示
> （其中故意包含一对同通道重叠提示，用于展示冲突标记）。之后所有增删改都持久化到该文件。

## 必要配置

均为**可选项**，不配也能直接跑（使用下面的默认值）：

| 配置项 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 宿主机访问端口 | `docker-compose.yml` 环境变量 `HOST_PORT` | `3000` | 例如 `HOST_PORT=8080 docker compose up -d --build` 后访问 http://localhost:8080 |
| 数据文件路径 | 容器内环境变量 `DATA_FILE` | `/app/data/cues.json` | JSON 落盘位置；Compose 默认把宿主机 `./data` 挂载到该目录 |
| 容器监听端口 | `PORT` | `3000` | 一般无需修改；改了需同步调整端口映射 |

需要自定义时，可在项目根目录创建 `.env`，例如：

```env
HOST_PORT=8080
```

## 不用 Docker 的本地运行方式

可用环境变量：`PORT`（默认 3000）、`DATA_FILE`（默认 `./data/cues.json`）。

## 使用说明

1. **新增提示**：在「新增提示」表单填写名称、独占通道、持续秒数，选择开始方式（固定秒数 / 另一提示结束后延迟），点击「保存新增」。
2. **编辑提示**：点击时间轴上的色块，或列表中的「编辑」。修改保存后，所有后继提示立即重算，时间轴即时刷新。
3. **冲突处理**：同通道重叠的提示块变红，时间轴上以红色斜纹标出**冲突时段**，下方「通道冲突」面板列出重叠的秒数区间。冲突**不会阻止保存**，可保留供排练调整；首尾相接不算冲突。
4. **删除提示**：若仍有其他提示以它为前置，会被拒绝（HTTP 409）并提示具体引用者，需先调整这些提示，避免产生悬空引用。
5. **片段排练单**：在「✂️ 片段排练单」面板输入时间窗 `[起, 止)` 秒数（左闭右开、正长度），点「预览片段单」查看片段时间轴、入选提示与片段内通道冲突；确认后点「下载片段 JSON」保存独立提示单。**原提示单不会被修改**。窗口非法会提示具体原因；若源提示有「时间未定」的条目，需先解决其引用/环问题再截取。

### 校验与拒绝规则

- 名称 / 通道不能为空，持续秒数、固定秒数、延迟秒数必须为非负数；
- 相对开始引用的提示必须存在，否则**拒绝保存**；
- 不允许把自己设为前置；任何**循环依赖**（含多节点环）都会被检测并**拒绝保存**，已在环上的提示在页面上标记为「时间未定」；
- 保存采用全量校验：新数据有问题时整次写入回滚，磁盘上的数据不受影响。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/cues` | 返回全部提示、重算后的时间表 `schedule`、冲突 `conflicts`、图错误 `graphErrors` |
| `POST` | `/api/cues` | 新增提示并全量重算；引用/环问题返回 400 |
| `PUT` | `/api/cues/:id` | 修改提示并重算所有后继；非法修改返回 400 并回滚 |
| `DELETE` | `/api/cues/:id` | 删除提示；仍被引用时返回 409 |
| `POST` | `/api/rehearsal` | 片段排练单预览（只读，不改动原提示单）。请求体 `{"window":{"start":30,"end":80}}`；返回截取后的 `cues`、重算 `schedule`、片段内 `conflicts` 与 `adjustments`（哪些提示因前置未入选/跨左边界改为固定开始）。窗口非法返回 400；源提示时间未定时返回 409 |
| `GET` | `/healthz` | 健康检查 |

`POST /api/rehearsal` 响应示例（节选）：

```json
{
  "window": { "start": 30, "end": 80 },
  "cues": [
    { "id": "cue-b1", "name": "主角上场追光", "channel": "追光 B", "duration": 20,
      "startType": "fixed", "fixedAt": 0, "afterCueId": null, "delayAfter": 0 }
  ],
  "schedule": [{ "id": "cue-b1", "start": 0, "end": 20, "reason": null }],
  "conflicts": [],
  "adjustments": [{ "id": "cue-b1", "from": "after", "to": "fixed", "reason": "pred-excluded" }]
}
```

`adjustments[].reason` 为 `pred-excluded`（前置未入选）或 `cross-left`（提示跨左边界）。页面下载的 JSON 形如 `{"kind":"rehearsal-cue-sheet","sourceWindow":{...},"cues":[...]}`，`cues` 结构与上表提示对象一致，可作为独立提示单使用。

提示对象示例：

```json
{
  "name": "第一幕追光",
  "channel": "追光 B",
  "duration": 20,
  "startType": "after",
  "afterCueId": "cue-a1",
  "delayAfter": 5
}
```

`startType: "fixed"` 时使用 `fixedAt`（固定开始秒数），`afterCueId` 传 `null`、`delayAfter` 传 `0`。

```
│   ├── index.html

│   └── app.js         # 原生 JS：时间轴、冲突面板、编辑表单
└── data/
    └── cues.json      # 运行后自动生成（被 .gitignore 忽略）
```
